# Bounce Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Bounce, a fourth cut procedure (triplet bounces, stepped ratchets, halftime bars), as Livecut 0.2.0.

**Architecture:** Bounce is a stateless `CutProcedure` in the JUCE-free engine. Its only engine prerequisite is that `LivePlayer` honours a *pitched-down* first cut, with `scatter` changed first so SQPusher sounds the same. The plugin layer adds four parameters, a fourth procedure choice and its editor controls.

**Tech Stack:** C++20, JUCE 9.0.4 (plugin layer only), Catch2 v3, CMake, gh-stack.

**Spec:** `docs/superpowers/specs/2026-10-19-bounce-procedure-design.md` (read it first; this plan cites its sections rather than repeating them).

## Global Constraints

- The engine (`src/engine`) stays JUCE-free C++20: no allocation, locks or added latency on the audio thread, and randomness only through the engine's `Random`.
- Same seed and host position give the same cuts on every platform.
- No existing parameter ID is renamed or removed; existing parameters keep their ranges and defaults.
- CutProc11, WarpCut and SQPusher must sound exactly as before.
- Every new source file starts with `// SPDX-License-Identifier: GPL-3.0-or-later`.
- The code compiles cleanly under `juce_recommended_warning_flags`: no exact float comparisons (use a tolerance), no shadowed names, no missing prototypes (put test helpers in an anonymous namespace).
- Red, then green: every behaviour gets a failing test first.
- Build and test with the dev tree: `cmake --build build/dev --target LivecutEngineTests LivecutTests -j 10`, then `./build/dev/LivecutEngineTests` and `./build/dev/LivecutTests`. The whole suite must pass before each commit.
- Commit messages are plain English sentences in the repository's style (e.g. "Let a live first cut be pitched down") and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Layer 1 (Tasks 1–5) lives on `bounce/engine`; layer 2 (Tasks 6–8) on `bounce/plugin`, created with `gh stack add bounce/plugin` after Task 5. Use `GH_STACK_NO_UPDATE_NOTIFIER=1` and the non-interactive forms from the gh-stack skill.

## Review Focus

- **A tempo change while a pitched-down first cut plays** (`LivePlayer::setSamplesPerUnit`) must keep it sounding for its new gated length. A naive fix that only patches `startBlock` would leave it silent. Test added to Task 2.
- **A phrase that starts off the beat or inside the ratchet zone** (after the cutter resets mid-bar) must recover onto the beat and never start a ratchet part way through the zone. Test added to Task 3.
- **Beats that aren't whole units**, such as 6 units per bar in 4/4 (1.5 units per beat) or 7/8 (3.5 beats per bar), must still add up exactly and keep blocks off bar lines. Test added to Task 3.
- **A bar near the 8-second limit** with a halftime bar must stay within the recording buffer (the player asserts `size <= capacity` in debug builds) and still sound. Test added to Task 5.
- **Climb at 0** must give a ratchet with no pitched cuts at all, not cuts pitched by 0 cents that take the resampling path. Test added to Task 4.

### Task 3: Bounce's groove and bounce moves

**Files:**
- Create: `src/engine/Bounce.cpp`
- Modify: `src/engine/CutProcedures.h` (declare `Bounce`), `src/engine/Cut.h` (new `CutParameters` fields), `CMakeLists.txt` (add `src/engine/Bounce.cpp` to `LivecutEngine` and `tests/engine/BounceTests.cpp` to `LivecutEngineTests`, both alphabetically)
- Test: `tests/engine/BounceTests.cpp`

**Interfaces:**
- Produces:
  - `class Bounce final : public CutProcedure { public: void chooseBlock (Random&, const CutParameters&, const BlockContext&, std::vector<Cut>&) override; };` declared in `CutProcedures.h` with a one-line comment in the style of its neighbours.
  - In `CutParameters`, under a `// Bounce` heading: `double bounceChance = 0.4;`, `double ratchetChance = 0.7;`, `int climb = 7; // semitones` and `double halftimeChance = 0.15;`.

Implement the spec's **Musical model** rules and moves 3 (Bounce) and 4 (Groove) now. Leave ratchet and halftime for Tasks 4 and 5, but compute the ratchet zone's start here, because blocks must never cross it.

The block-choosing steps, in order, with `eps = 1e-9` and all lengths in units:

```
beat     = unitsPerBar / beatsPerBar
intoBar  = unitsDone - floor((unitsDone + eps) / unitsPerBar) * unitsPerBar
zone     = min((unitsPerBar >= 2 * beat - eps ? 2 : 1) * beat, unitsPerBar)
zoneStart = phraseUnits - zone
boundary = min(unitsPerBar - intoBar, phraseUnits - unitsDone,
               unitsDone < zoneStart - eps ? zoneStart - unitsDone : +inf)
offBeat  = intoBar / beat is not within eps of a whole number
if offBeat: groove to min(next beat, boundary)
elif boundary >= beat - eps and chance(bounceChance):
    chance(0.5) ? three cuts of beat/3 : cuts of 2*beat/3 then beat/3
else: groove of (chance(0.5) ? 2 : 1) * beat, clipped to boundary
```

Groove and bounce cuts take `gate = dutyCycle` and `amp = uniform (minAmp, maxAmp)` per cut, with pan 0 and cents 0.

- [ ] **Step 1: Write the failing tests** in `BounceTests.cpp`, using `playPhrase` from `EngineTestHelpers.h`. Loop over seeds 1–50 and `GENERATE` unitsPerBar (6, 8, 16, 32) and beatsPerBar (4.0, 3.0, 3.5):
  - `"Bounce blocks never cross a bar line or the ratchet zone"`: for every block, `floor((start + eps) / unitsPerBar) == floor((end - eps) / unitsPerBar)`, and no block both starts before and ends after `phraseUnits - zone`. `playPhrase` already checks that the phrase adds up.
  - `"At full Bounce every whole on-beat beat is a triplet"` (`bounceChance = 1`, `ratchetChance = 0`, `halftimeChance = 0`): every block that starts on a beat and lasts one beat is either 3 cuts of beat/3 or 2 cuts of 2·beat/3 then beat/3 (within 1e-9), and both shapes occur across the seeds. Every other block has one cut.
  - `"With Bounce off every block is a single straight cut"` (all three chances 0): one cut per block with `cents == 0`, lasting 1 or 2 beats, or less only when it is clipped to a boundary.
  - `"A phrase that starts off the beat gets back onto it"` (Review Focus): set `BlockContext::unitsDone` to 1 unit with 6 units per bar in 4/4, choose one block, and assert it ends on a beat (intoBar a whole multiple of 1.5).
  - `"Bounce is deterministic"`: two runs with the same seed give identical blocks.
- [ ] **Step 2: Run** `./build/dev/LivecutEngineTests "[bounce]"` **and see them fail** (Bounce doesn't exist yet).
- [ ] **Step 3: Implement `Bounce::chooseBlock`** in `Bounce.cpp`, with a file header like `WarpCut.cpp`'s that says Bounce is new to this port, not from BBCut.
- [ ] **Step 4: Run the whole engine suite; everything passes.**
- [ ] **Step 5: Commit:** "Add Bounce's straight and triplet moves".

### Task 4: Bounce's ratchet

**Files:**
- Modify: `src/engine/Bounce.cpp`
- Test: `tests/engine/BounceTests.cpp`

**Interfaces:**
- Consumes: Task 3's `zone`, `zoneStart` and boundary rules.
- Produces: the spec's move 1, Ratchet.

A ratchet block covers the zone with 12 cuts: 3 of zone/6, then 3 of zone/12, then 6 of zone/24. Step `k` (0, 1, 2) has `cents = 100 * round(climb * k / 2.0)`. The gate is `fillDutyCycle`. Pan and amplitude come from `sweep (cuts, random, params)`, called before the steps' `cents` are written over its pitch. Roll `chance (ratchetChance)` only when `unitsDone` is within eps of `zoneStart`.

- [ ] **Step 1: Write the failing tests:**
  - `"At full Ratchet every phrase ends in a stepped ratchet"` (`ratchetChance = 1`; seeds 1–50; the same unitsPerBar and beatsPerBar as Task 3): the last block starts at `phraseUnits - zone` and has 12 cuts with the lengths above (within 1e-9). `climb = 7` gives cents {0, 400, 700} by step; `climb = 12` gives {0, 600, 1200}.
  - `"With Ratchet off no phrase ends in a ratchet"`: no block has more than 3 cuts.
  - `"A ratchet with no climb keeps every cut at the original pitch"` (Review Focus; `climb = 0`): every cut's `cents` is within 1e-6 of 0.
  - `"A phrase that starts inside the ratchet zone never ratchets"` (Review Focus): `unitsDone` starts at `phraseUnits - zone + 0.5`, with `ratchetChance = 1`; no block has more than 3 cuts.
