# Livecut 1.0 Pad, Slice 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Livecut's settings pages with a playable XY pad and eight program buttons (layout B), driving the existing cut engine. Cut, Bounce and Glitch are playable.

**Architecture:**
- Programs are pure functions in the plain-C++ engine: `(program, x, y) → cut settings`, with zone hysteresis.
- A sample-accurate `PadGate` in the engine turns touch, Hold and Quantize into a wet gain, an idle request and quantised program switches.
- Two new `Cutter` requests support it: going idle, and restarting at the next unit boundary.
- The processor applies the active program's settings at each render context and runs the gate inside `Observer::processOutput`.
- The editor gets a Pad page. The legacy pages stay behind a Classic switch, and saved 0.x states load as Classic.

**Tech Stack:** C++20, JUCE 9.0.4, Catch2 3, CMake. Engine code stays JUCE-free.

**Spec:** `docs/superpowers/specs/2026-11-01-livecut-1.0-pad-design.md`

## Global Constraints

- Never rename or reorder existing parameter IDs, indices, ranges or choices. The 106 existing parameters keep indices 0–105. New parameters append at 106–112 with JUCE version hint **9**.
- The `procedure` choice list stays exactly `{CutProc11, WarpCut, SQPusher, Bounce}`. `padProgram` has all eight choices from slice 1, so its normalised automation never changes later.
- State `schemaVersion` becomes **9**. `algorithmVersion` stays **2**.
- **Classic surface:**
  - It renders sample-identically to today's `main`.
  - Saved states without a `surface` entry load as Classic.
  - New instances default to Pad.
- **Audio thread:** no allocation, locks, waits or I/O in the callback. Cutter and gate requests made inside `processOutput` only set flags, which are consumed on the next rendered sample.
- **Fade and grid:** the release fade is exactly `std::lround (0.005 * sampleRate)` samples, linear. Release and program switches land on the first sample at or after the next beat line (Beat) or bar line (Bar), and that includes the current sample.
- **Wording:** user-facing copy describes sound, not machinery. No "block", "reader", "family" or "epoch" in pad UI text.
- **Process:**
  - RED/GREEN for every behaviour.
  - Match the surrounding code style (spaces before call parentheses in `src/`, Allman braces) and SPDX headers.
  - Commit after each task.
  - Use no new dependencies.

## Review Focus

1. **A quick tap** (press and release within one unit) still cuts until the next beat, then fades. It is never cut short or left stuck on. Test in Task 3.
2. **Different host buffer sizes** (1, 37, 512, 4096 samples) give bit-identical output for the same touch timeline. Test in Task 5.
3. **Touching while the transport is stopped** stays dry and doesn't fault. When playback starts with the touch still held, cutting begins on the next unit boundary. Test in Task 5.
4. **Automation selecting a program not yet built** (Suction to Rush) stays dry and reports it. It never substitutes another program. Tests in Tasks 3 and 5.
5. **Seeking or looping the transport while engaged** gives no fault, and cutting resumes on the grid in the new region. Test in Task 5.

### Task 2: Cutter idle and restart (engine)

**Files:**
- Modify: `src/engine/Cutter.h`, `src/engine/Cutter.cpp`
- Test: `tests/engine/CutterTests.cpp` (append)

**Interfaces:**
- Produces, as `Cutter` public members:
  - `void setIdle (bool idle)`. It records a request, applied at the start of the next `renderOne`.
    - Going idle while cutting drops the phrase, the queued plans and the player's playing cuts, which is `livePlayer.resetRendering()`, and emits `observer->discontinuity (sampleOffset)`.
    - While idle, no phrase starts and the input passes through.
    - Leaving idle uses the existing rule that a phrase starts on the next unit boundary.
  - `void restartAtNextUnit()`. Ignored while not cutting. Otherwise, at the first rendered sample on a unit boundary of `pendingUnitsPerBar`, within half a sample, it:
    1. emits `discontinuity`;
    2. clears the plans and `livePlayer.resetRendering()`, keeping the effects, raw history and render context;
    3. calls `startPhrase (bar, boundary, timing)`, which applies the structural changes;
    4. emits `phraseStarted (offset, boundary == 0)`.
  - `Position renderPosition() const`. It returns `{renderBar, renderBeats}` for the sample being rendered, and is valid inside `Observer::processOutput`.
- Consumes: nothing new.

### Task 3: PadGate (engine)

**Files:**
- Create: `src/engine/PadGate.h`, `src/engine/PadGate.cpp`
- Modify: `CMakeLists.txt`
- Test: `tests/engine/PadGateTests.cpp`

**Interfaces:**
- Consumes: `PadProgram` and `isAvailable` from Task 1.
- Produces:
  - `enum class PadQuantize { beat, bar };`
  - `class PadGate` with:
    - `void prepare (double sampleRate);`
    - `void reset();`: closed, idle, no pending switch and no latch. The active program keeps its value.
    - `struct Input { bool alwaysEngaged = false, touch = false, hold = false; PadProgram program = PadProgram::cut; PadQuantize quantize = PadQuantize::beat; };`
    - `struct Step { float gain = 0.0f; bool idle = true; bool programChanged = false; };`
    - `Step process (const Input&, double beatsIntoBar, double beatsPerBar, double beatsPerSample);`
    - `PadProgram activeProgram() const;`
    - `std::optional<PadProgram> pendingProgram() const;`
    - `bool engaged() const;`
- Rules, one call per sample:
  - `latch = hold && (touch || latch)`. `want = isAvailable(program) && (alwaysEngaged || touch || latch)`.
  - **Closed and want:** open at this sample with gain 1 and idle false. If the program differs from the active one, it becomes active and `programChanged` is true.
  - **Open and not want:** a release is armed. At the first sample at or after the next boundary, the gain falls linearly to 0 over `lround(.005*sr)` samples, then idle is true and the gate is closed.
  - **want returns while the release is armed or fading:** the release is cancelled. While fading, the gain rises at the same rate back to 1. It never goes idle.
  - **Open, and an available program differs from the active one:** a switch is pending. At the next boundary the program becomes active and `programChanged` is true.
  - **Closed, and the program differs:** it becomes active at once with `programChanged` true. Nothing is audible.
  - **Boundary:** for Beat, `std::abs (beatsIntoBar - std::round (beatsIntoBar)) < .5 * beatsPerSample`. For Bar, `beatsIntoBar < .5 * beatsPerSample`.

- [ ] **Step 1: Write the failing tests**, with a per-sample driver at 120 BPM and 48 kHz, so a beat is 24,000 samples and the fade is 240 samples:

  - `"A quick tap cuts until the next beat, then fades over 5 ms"`:
    - press at beat .1 and release at beat .12;
    - gain is 1 up to the sample before beat 1;
    - gain reaches 0 at exactly 240 samples after beat 1;
    - idle is true from then on;
    - the gain decreases monotonically through the fade.
  - `"Bar quantize waits for the bar line"`.
  - `"Pressing again during the fade restores full gain without going idle"`.
  - `"Hold keeps the gate open after release, and turning Hold off releases on the next boundary"`.
  - `"A program switch lands on the next beat while engaged, and immediately while closed"`.
  - `"Programs not yet built never engage"`: Suction with touch keeps gain 0 and idle true.
  - `"Always engaged is open at every sample"`, for the Classic surface.
