# Livecut 1.0 Tape Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The pad's Tape program. Between stops it plays the track in place. Stops brake onto the grid, from once every four bars to every beat. The next hit winds up and lands back exactly on the track.

**Architecture:**
- `Cut` gains a per-cut `TapeMotion` (default `cycle`, today's Classic Tape).
- `FractureParameters::Tape` gains a `stops` layout, a stop length and a density.
- `TapeTrajectory` gains a quadratic brake and a catch-up curve.
- The pad's motions read from their own first frame with no fade, so no Tape cut ever splices.
- A pure `layOutTapeStops` places stops from the seed, the host bar and the beat.
- `PadMapping::fracture` carries Tape's mapping to the cutter.

**Tech Stack:** C++20, JUCE 9.0.4, Catch2 3, CMake. Engine code stays JUCE-free.

**Spec:** `docs/superpowers/specs/2026-11-02-livecut-1.0-tape-design.md`. Parent: `docs/superpowers/specs/2026-11-01-livecut-1.0-pad-design.md`.

> - **The bars are near the measurements.** The switch bars are 1.25× (1× to Classic). The drum tests' bars are recorded in the spec next to what they measure.

> - Stops blocks end exactly on their bar line.

## Global Constraints

- **Classic is unchanged:**
  - Classic Tape (cycle layout) and Grain are bit-identical, pinned by hashes taken before any engine change.
  - `LegacyEquivalenceTests` and every existing test pass unchanged.
  - The Classic Tape curve choice keeps exactly its two choices.
- **The other programs are unchanged.** Cut, Bounce, Glitch, Suction and Filter are bit-identical through the processor, pinned by a hash taken before any change.
  - The exception: tests that used Tape as "the unavailable program" move to Loops.
- **Audio thread:** no allocation, locks or I/O. No new parameters. `Cut` doesn't grow.
- **Values verbatim from the spec:**
  - brake `1 − u²`;
  - catch-up `p = T (3u² − 3u³ + u⁴)`, `v = 6u − 9u² + 4u³`;
  - gain `√min (v, 1)`, no fade;
  - spin-up ⅛ beat;
  - levels 0 to 4 from the host bar `(b + 1) mod 4` and `mod 2`, and even beats;
  - chance `clamp (density + 1 − level, 0, 1)`;
  - length `min (stopBeats, B, gap / 2)`, with `gap` looked back over two bars;
  - mapping: lengths {½, 1, 2, 4}[min (⌊4x⌋, 3)], density 4y, seed 606, 16 units.
- **Style and process:**
  - Allman braces, a space before call parentheses in `src/`, SPDX headers.
  - RED/GREEN for each behaviour.
  - Commit per task, ending the message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Classic's bits.** The `cycle` motion must take exactly today's path: speeds, Alternate, block source and fade envelope. The pinned hashes are the check.
2. **No splice.** At every Tape join the audio continues: the same frame at the same speed, or silence into silence. Bitwise equality with the input outside stops and spin-ups is the check.
3. **Causality.** The catch-up never reads ahead of the newest recorded frame.
4. **Determinism.** Selection depends only on (seed, host bar, beat). The spin-up flag is cleared on every drop.
