# Livecut 0.8.0 — Resonance

Four tuned resonator voices, three fixed effect orders, and a prepared Spectral Freeze / Smear stage extend the existing cut engine. These are audio processors: they operate on the source being cut, without generating replacement samples or changing the original procedure identities.

## Resonator and effect order

The root ranges from 40 to 800 Hz. Each voice has a semitone interval from -12 to +24 and a relative weight; weights normalize together. Decay specifies a pole T60 from 40 to 5000 ms, excitation ranges from -12 to +12 dB, and local Mix controls the blend. There is no hidden output limiter. All four weights at zero is an explicit invalid selection with silent resonator wet output; local dry remains available through Mix.

Tuning changes crossfade two fixed banks over 50 ms. A later request during that fade retains the latest pending tuning. Enable and local Mix use 2 ms ramps. Parameters follow the existing next-planned-block contract.

The three orders are Impact → Resonator → Frequency, Resonator → Impact → Frequency, and Impact → Frequency → Resonator. Changes begin on a bar boundary and crossfade for 5 ms. Both lanes share the same frozen cut identity and selection; the transition does not draw new cutting randomness. A newer route request waits for a subsequent eligible bar when a transition is already active. Crusher and Comb stay before this rack, and Spectral stays after it.

## Spectral Freeze / Smear

Spectral Engine is a prepared configuration, saved with the project and applied while stopped. It is deliberately not an automatable parameter because enabling it changes declared latency and allocates prepared storage. Freeze, Smear and Spectral Mix are automatable.

Freeze captures the next eligible full analysis frame, holds magnitudes and continues phase evolution. Smear is a hop-rate magnitude smoothing time constant from 0 to 2000 ms; zero disables smoothing. It is not an amplitude decay guarantee. Spectral Mix blends the processed signal before Spectral with the spectral output. Audio Hold remains a separate phrase-looping processor after Spectral. Project state stores the controls, not the captured spectral audio. Loading a project or starting a new transport epoch requires fresh analysis; a saved Freeze request captures the next eligible frame.

An FFT worker performs the analysis and synthesis. The realtime callback submits bounded immutable chunks and consumes tagged results; it does not execute an FFT, wait for the worker, or allocate storage. Explicit offline processing may wait with lifecycle cancellation. A missed deadline, invalid packet or worker fault latches an error and gates output until stopped reconfiguration; there is no dry substitution or automatic catch-up.

The transform size is `N = bit_ceil(ceil(sampleRate / 48000 * 4096))`, the hop is `N / 4`, and the prepared delay is `2 * N`. Studio's existing 500 ms lookahead is additional; the cut engine does not consume the spectral delay as extra lookahead.

| 8 kHz | 2,048 | 256 ms |
| 44.1 kHz | 8,192 | 185.76 ms |

| 96 kHz | 16,384 | 170.67 ms |

Configured Spectral retains its declared delay at Mix 0 and under host bypass. Host bypass selects the aligned original raw input. With Spectral Engine disabled, the original Live zero-delay and Studio 500 ms contracts remain unchanged.

After a start or seek, Spectral reports Waiting, then Priming, then Ready. Very short repeated transport epochs may never become Ready. While warming, the spectral contribution is silent; only an explicitly selected local dry contribution remains. This availability delay is separate from the declared compensation delay. The editor's source and effect diagnostics follow the delayed heard output.

## Hold, Capture and state

Hold does not admit a fresh candidate containing unavailable spectral wet audio, while retaining a previously valid held phrase. Capture records the final heard output. A captured phrase that passed through spectral warm-up carries the immutable annotation “Captured while spectral path was warming”; this does not claim that the entire phrase was silent, because dry or held audio may have been heard.

All 88 pre-existing parameter identities and indices remain fixed. Eighteen controls are appended with version hint 8; state schema becomes 8 while the cutting algorithm remains version 2. Loading an older project restores default-disabled Resonator and Spectral settings, including when loading into an already-adjusted instance.

## Validation status

Local validation passes 269 engine cases (6,801,109 assertions) and 141 processor/UI/state cases (472,984 assertions). The full engine suite also passes AddressSanitizer and UndefinedBehaviorSanitizer; 22 focused spectral/processor cases pass both sanitizers with 433,408 assertions. LeakSanitizer is disabled because this macOS runtime does not support it. Regression tests cover source and event ownership, latency/bypass alignment, lifecycle cancellation, and Freeze/Smear changes at seek boundaries.

Final platform CI, exact packaged VST3 and native host checks are release gates. The unpublished GitHub draft will identify the exact assets and completed verification scope; local tests alone do not establish native host or package validation.
