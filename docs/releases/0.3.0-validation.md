# Livecut 0.3.0 implementation validation

Local environment: Apple Silicon macOS, AppleClang 21, CMake, pinned JUCE 9.0.4
(`3fb5cbc0340758596dac39f7c8de47d562b4896e`) and Catch2 3.16.1.

## RED

Before implementation, compiled `LivecutTests '[capture]'` against the 0.2.0
sources. All three new feature cases failed (four assertions): no Wet parameter,
no capture controls, and absent schema/algorithm versions.

During integration, independent review identified an exact-buffer-end completion
gap and durable job status hiding live readiness/capacity. Two focused regression
cases were run against the affected implementation and failed five assertions.
They cover a completed phrase ending at the host buffer end before stop/loop,
and failed early capture followed by readiness / saved snapshot followed by an
oversized candidate. The corrected implementation passes both.

The exact classic-output check also caught nonzero normalization rounding at the
asymmetric trim range's default. The symmetric −24 to +24 dB range gives an exact
0 dB default and passes bit-for-bit equivalence.

## GREEN

Commands:

```sh
cmake -S . -B build-capture -DCMAKE_BUILD_TYPE=Debug -DCMAKE_OSX_ARCHITECTURES=arm64
cmake --build build-capture --target LivecutTests LivecutEngineTests --parallel 6
ctest --test-dir build-capture --output-on-failure
cmake -S . -B build-capture/release -DCMAKE_BUILD_TYPE=Release -DCMAKE_OSX_ARCHITECTURES=arm64
cmake --build build-capture/release --target Livecut_VST3 Livecut_AU Livecut_Standalone --parallel 6
cmake -DRELEASE_TAG=v0.3.0 -P packaging/check-release-version.cmake
```

- Full Debug suite: **152/152 tests passed**, 22.03 seconds.
- Capture tests cover only complete phrases, exact capacity and oversize rejection,
  stopped/seek retention, long-held immutable leases, 10,000 concurrent publication
  iterations, lease lifetime across preparation, independent captured snapshots,
  exact stereo float WAV samples/rate/channel count (including values above 1),
  write errors and exact user-selected filenames.
- Processor integration covers multiple boundaries in one buffer, end-boundary
  completion before stop/loop, zero allocations with a leased export and repeated
  boundaries, exact classic-output equivalence for all four procedures, and old
  state restored onto previously adjusted controls.
- At **44.1 / 48 / 96 kHz**, an actual sample comparison checks a whole phrase
  whose tempo changes from 120 to 90 BPM mid-phrase. Meter changes discard the
  in-progress candidate and the next complete 3/4 phrase replaces it.
- Engine event tests prove sample offsets across multiple boundaries and prevent
  double completion after an exclusive-end event.
- Editor tests cover all parameter/control IDs, capture/save enablement and a
  background capture finishing after editor destruction. The generated editor
  screenshot is `docs/editor.png`.
- The release-version guard's eight positive/negative fixtures pass, and the
  actual `v0.3.0` tag/version comparison passes without pushing a tag.

## Scope of this record

Local Release bundles are ARM64. CI must still produce/validate universal macOS
and Windows release artifacts and perform signing/notarisation. The local build
does not install into user plug-in folders. No PR, tag, release, listening test or
manual DAW/export/import validation is claimed by this implementation record;
the coordinating task tracks those steps separately.
