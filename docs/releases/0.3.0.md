# Livecut 0.3.0 — Capture

Capture the last fully completed natural Cutter phrase and save exactly what
left the plug-in as a stereo 32-bit IEEE float WAV at the processing sample rate.
Global Wet and Trim controls make subtle parallel processing available.

## Using Capture

1. Play through a whole phrase. The capture status shows when a complete phrase
   is ready. Starting or seeking in the middle of a phrase waits for the next
   full phrase; partial audio is never offered as a completed phrase.
2. Press **Capture last phrase** to keep the most recently completed phrase.
   Copying runs on a background worker. Capturing again replaces that snapshot.
3. Press **Save WAV...** and choose a file. Saving uses the exact selected path
   and replaces it only through the native save dialog's overwrite flow.

Stopping, seeking or a meter change discards the in-progress candidate. A
previous complete phrase remains available to capture after stopping, without
needing another running audio callback. A successful captured snapshot remains
available independently of subsequent playback, stopping and sample-rate changes.
WAV files preserve values above 0 dBFS; they are not normalized or clipped.

**Wet** uses a linear blend from dry input to the Cutter and its effects.
**Trim** runs after that blend, from −24 to +24 dB, including when transport is
stopped or timing cannot be cut. Both controls use a 20 ms linear ramp. Defaults
are 100% Wet and exactly 0 dB Trim, preserving the previous release's output.

## Bounds and ownership

The recorder prepares two stereo float buffers for up to 64 seconds each,
covering the engine's longest phrase: eight bars at eight seconds per bar.
Capacity is capped at 12,288,000 frames per buffer, so rates above 192 kHz have
less than 64 seconds available. A phrase that exceeds capacity is rejected in
full, with a visible capacity message; any previous completed phrase is explicitly
identified as still available. Nothing is silently truncated.

The two buffers use approximately 49.2 MB at 48 kHz, 98.3 MB at 96 kHz and
196.6 MB at 192 kHz, in decimal MB, excluding the existing cutting engine.
Pressing Capture allocates an independent snapshot of only the completed phrase
(up to another 24.6 / 49.2 / 98.3 MB at those rates). Preparing a new sample rate
while a worker holds a lease temporarily keeps that old leased storage alive.
File writing uses small fixed-size chunks rather than a whole-file conversion.

Audio-thread ownership is handed to the capture worker with atomic slot states.
The callback neither allocates, waits nor copies a complete phrase. If the worker
still leases the prior slot at the next phrase boundary, that new candidate is
skipped and a busy message appears; recording continues. Snapshot copying and
WAV creation run off the callback, and an editor can close while a job finishes.

## State and compatibility

Existing parameter IDs, indices, ranges and random seed behavior remain stable.
Wet and Output Trim are appended with AU parameter version hint 3. Saved state
adds `schemaVersion=3` and `algorithmVersion=2`; unversioned older state remains
readable. Missing controls restore their defaults even on an already adjusted
instance. Captured audio is transient and is not embedded in DAW project state.

Hold, file drag-out, time-stretching and look-ahead are outside 0.3.0.

## Validation

The initial compiled feature tests failed on 0.2.0 for absent mixer controls,
capture UI and state version properties. Additional failing regressions proved
the exact-buffer-end stop/loop case and stale status text before their fixes.
The validation record is in `0.3.0-validation.md`. Automated processor tests and
editor rendering are not listening or manual DAW validation.
