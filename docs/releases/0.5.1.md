# Livecut 0.5.1 — Recut

0.5.1 is the corrected release of the 0.5 feature line: **500 ms Studio
lookahead, Attack Align and deterministic Reverse Chance**, with Live mode and
neutral transforms as the defaults. Capture, WAV export, Audio Hold, Swing,
Accent, Wet and Output Trim remain available. See the
[Recut behavior and capacity guide](0.5.0.md) and
[measured memory budget](0.5.0-memory.md) for the feature contracts and limits.

## Corrected host restart behavior

Native validation of the signed 0.5.0 draft found that applying Studio in Ableton
Live 12.4.6 could leave the host repeatedly deactivating and reactivating Livecut.
The plug-in reported zero latency when audio resources were released, then
reported Studio's latency when prepared again. Each change could request
another host restart. The 0.5.0 draft was held and was not published.

0.5.1 keeps the configured latency separate from the lifetime of audio buffers.
A normal host deactivation releases resources and gates audio while retaining
the declared latency. Successful preparation or mode Apply establishes the next
latency; a preparation failure remains an explicit error with zero declared
latency. The generation and reentrant-notification coordination remains intact.

At 48 kHz, Studio therefore retains its 24,000-sample declaration through a
normal deactivate/reactivate cycle. This does not imply that the host has
acknowledged or applied delay compensation, and it does not remove the delay
heard when monitoring live input.

The 0.5.0 tag is preserved for provenance. Use 0.5.1 for the corrected Recut
release. The cutting algorithms, source eligibility, detector, parameters and
state schema are unchanged by this lifecycle correction.

## Validation

The new deferred-host-restart regression failed against unchanged 0.5.0:
at 48 kHz it recorded alternating 24,000/zero latency notifications, and four
bounded restarts left five more queued. The corrected processor passed the
Recut suite: 28 cases and 590 assertions, including 8 kHz and 48 kHz restart
convergence, Live/Studio transitions, gated released output, resumed exact
impulse delay, preparation errors and existing reentrant/stale-generation cases.

A separate actual VST3 host harness reproduced the same nine alternating
notifications on the signed 0.5.0 bundle, with deferred lifecycle calls outside
the notifying callback. Its four-restart cap failed explicitly while the
resumed impulse still had the correct 24,000-sample delay. This distinguishes
host-lifecycle convergence from the already passing DSP delay tests.

All **277 CTest cases passed** after the correction. Independent review of the
immutable production fix found no actionable issues, including its generation,
error, stale-operation and normal-release behavior.

The corrected wrapped-VST3, cross-platform CI, package verification and signed
native Studio Apply checks are subsequent release gates. Their results are
recorded with the [GitHub release](https://github.com/seandearnaley/livecut/releases)
and local validation evidence. Automated processor tests alone do not establish
a native DAW pass. Publication remains with the repository owner.
