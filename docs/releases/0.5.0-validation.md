# Livecut 0.5.0 implementation validation

## Common renderer milestone

Before production changes, compiled separate-render tests were RED: 16 failed
assertions because Cutter lacked separate physical ingestion and original-context
rendering. Log: `/tmp/livecut-v05-seam-red.log`.

The common renderer retains the original callback's beat accumulator through
output callback splits. Source origins use explicit render frames and classic
pitched retiming uses render-exclusive-end r+1. Rendering resets retain physical
history; duplicate input and out-of-order render frames report explicit errors.

Full engine suite GREEN: **158 cases / 4,295,971 assertions**. This includes all
four procedures, 50/75% Swing, 137/512-frame original contexts, 500 ms delayed
rendering, pitch/pan/fades/crusher/comb and a tempo change, plus the unchanged
immutable 0.3 Live oracle. The delayed comparison accumulates sample equality
and allocation checks without per-sample Catch assertions. Log:
`/tmp/livecut-v05-seam-all-engine.log`.

This milestone does not yet claim processor Studio mode, transforms, mode Apply,
UI, wrapped-host validation, or manual listening.

## Mode Apply / lifecycle checkpoint

RED2 cases /2 failing assertions established the missing coordinator and the
unprepared bypass gap: bypass passed .5 input despite the normal unprepared
path gating it. Both paths now gate unsupported/unprepared audio explicitly.
Log: `/tmp/livecut-v05-apply-red.log`.

Apply prebuilds only StreamResources off audio and outside the callback guard;
sample-rate preparation also prebuilds Hold/capture storage and installs it
under exclusion. CaptureService stays stable and retired storage/resources are
destroyed after our guard is released. Existing leases retain old storage.

One callback-guard-protected claim owns latency notification while its listeners
run off-guard. Nested/concurrent prepare/release leave pending work rather than
call another setter or wait. The owner reconciles the latest generation/rate,
bounded to two attempts per message turn, then retries on a later timer turn.
No claim is made about host-owned locks around host lifecycle calls.

Permanent tests use real JUCE processor listeners to synchronously prepare at
16kHz or release during setLatencySamples; a separate thread successfully takes
the callback guard in that listener. A measured impulse after reprepare lands
at8000 frames, matching the new16kHz resources. Eight concurrent preparations
racing eight Apply attempts cannot restore an obsolete candidate. Fresh audio
observations are invalidated on EVERY prepare and successful mode-resource
swap; release evidence cannot authorize a subsequent prepared configuration.
Healthy Live bypass observes running/stopped transport without advancing audio.

Additional RED13 assertions /2 cases exposed reused observation evidence and a
numeric-latency-only fast path that skipped final publication/resume after
bounded reentrant host churn. That fast path was removed: even an already
configured mode reconciles publication/suspension through the owner protocol.
Log: `/tmp/livecut-v05-observation-red.log`.

Focused GREEN: **70 processor/parameter/host-sync/capture cases /35,100
assertions**. Log: `/tmp/livecut-v05-apply-green.log`. Tests also restore saved
requested Studio before prepare and while existing Live audio plays, and restore
a0.4 state onto all four already-adjusted Recut controls. Requested, configured
and published active mode remain separate; UI latency uses an atomic published
snapshot. Four editor control-coverage assertions and unfinished transforms
remain outside this partial internal checkpoint's scope.

### Coordinator foundation correction

Two related review cases were reproduced before changing the shared rule:
missing host PositionInfo after a playing callback was falsely treated as stop,
and prepare-to-16kHz followed by release during the two latency notifications
left an unpublished empty configuration suspended. RED: **2 cases /10 failing
assertions**, `/tmp/livecut-v05-reconcile-red.log`.

A single atomic unknown/stopped/playing observation now requires explicit stopped
transport for a runtime mode replacement; missing playhead/position information
is unknown in normal and bypass callbacks. Every preparation or mode replacement
invalidates old observations. Hosts, including standalone configurations, which
supply no transport cannot authorize runtime Apply; initial/device preparation
still authoritatively applies the persisted requested mode. No substitute clock
or inferred stop is used.

A callback-guard-protected published generation now establishes configuration
coherence before every mode-choice early return. Empty and failed preparation
generations therefore finish latency publication and resume the defined gated
path on retry, independently of mode eligibility. The setter claim still owns
notification and reentrant reconciliation. Added permanent coverage also replaces
the second notification with unsupported-rate preparation: retry publishes error,
zero latency, resumes, and normal/bypass both remain zero.

Focused GREEN: **72 cases /35,140 assertions** including fresh-observation,
reentrant, concurrent, numeric-match, empty/error retry, state and capture cases.
Log: `/tmp/livecut-v05-reconcile-green.log`. This remains an internal checkpoint;
transform integration and the final full-suite/release validation are pending.

A further deterministic ownership regression pauses an obsolete Apply prebuild
at a test-only one-shot allocation interleave, completes a newer authoritative
16kHz preparation/publication on another thread, then resumes the obsolete work.
Both its success and bad_alloc catch overwrote the newer active status: RED
**1 case /2 assertions**, `/tmp/livecut-v05-stale-red.log`. No extra Apply is
used in the assertion path. Stale generations now leave the newer generation's
state and retry flag untouched; same-generation request mismatch explicitly
schedules a retry. The test introduces no production injection seam.

Approved fixed-span Player and compact Recut UI leaf commits are integrated.
UI Apply fixtures now provide explicit stopped PositionInfo. Focused processor,
parameter, host-sync, capture and editor GREEN: **88 cases /35,470 assertions**,
`/tmp/livecut-v05-stale-green.log`. Final Cutter transform integration remains
pending.

## Integrated cut transform checkpoint

Cutter selection compiled RED **4 cases /5 failed assertions** before the
transform-selection API existed (`/tmp/livecut-v05-selection-red.log`). Each
BlockPlan now latches transform controls and nominal source identity. At the
current cut's first sample, selection verifies the complete physical source
span and fresh exact transport-epoch bounds, before choosing the nearest
eligible cached attack. Enabling Attack Align conditions reverse eligibility;
no qualifying complete attack leaves an explicit ineligible ordinary cut.
Reverse decisions use an independent stateless hash and consume no musical or
effect RNG draws. Fixed-span Player freezes source, rate, direction and N.

Focused selection GREEN **7 cases /104 assertions** includes linked stereo
forward/reverse preroll, incomplete Live input, cached original-context epoch
closure becoming known before a later cut, block-latched controls, and exact
repeatable reverse output with unchanged cuts/effect draws for all four
procedures at50/75% Swing. All callback allocation checks are zero. A transient
fixture was moved from frame80 to96 to respect the detector's80-frame refractory
gap after the initial-window marker; no detector policy was changed.

Real processor tests verify transformed wet audio is mixed once with the
original delayed dry audio and trim, publishes applied counters, and completes
a stereo final-output capture exactly matching heard output. A32-unit fixture
keeps the first full source inside Studio's500ms lead; longer unavailable sources
correctly remain ineligible. Focused processor/editor GREEN **36 cases /666
assertions**, `/tmp/livecut-v05-transform-processor-green.log`.

Full engine GREEN **186 cases /4,298,538 assertions**, including unchanged
0.3 oracle, the complete64s+lead+search+preroll retention/reverse test and its
missing-preroll canary. Log: `/tmp/livecut-v05-transform-engine-green.log`.
Final full CTest, Release bundles, validators, memory accounting, component
screenshots and immutable independent review remain separate gates.
